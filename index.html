MODULE 04

Deadlock Prevention: Fixed Resource Order

The policy requires resources to be acquired in one global order: R1 before R2. A process holding R2 must not request R1.

1
Allowed order

Acquire R1 first, then R2.

2
Rejected order

Holding R2 and requesting R1 violates the policy.

Choose a held resource and a requested resource.

Original scenario

P0 holds R1 and waits for R2, while P1 holds R2 and waits for R1.

P0→P1→P0

Circular wait can occur

With fixed ordering

Processes follow R1 → R2. A backward request is rejected, preventing this circular-wait pattern if all acquisitions obey the rule.

R1→R2

Circular wait prevented by ordering

Trade-offs

  • Benefit: prevents circular wait when every process follows the global order.
  • Cost: reduces flexibility; a process may need to acquire a resource earlier than it otherwise would.
  • Important: the policy checker validates acquisition order only. It does not check whether the requested resource is currently available.
